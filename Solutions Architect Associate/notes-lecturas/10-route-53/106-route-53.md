## Antes de empezar: conceptos y siglas

- **AWS — Amazon Web Services:** proveedor de servicios de nube utilizado en estas notas.
  - **Ejemplo:** AWS opera servicios de computación, almacenamiento, bases de datos y redes.
- **Route 53:** servicio administrado de DNS, registro de dominios y comprobaciones de estado de AWS.
  - **Ejemplo:** una zona de Route 53 puede dirigir `www.example.com` hacia una aplicación.
- **DNS — Domain Name System:** sistema que traduce nombres de dominio a información para localizar servicios.
  - **Ejemplo:** devuelve una dirección IP para `api.example.com`.
- **Registro DNS:** entrada que define la respuesta para un nombre y tipo determinados.
  - **Ejemplo:** un registro `A` relaciona `www.example.com` con una IPv4.
- **Hosted zone (zona alojada):** contenedor de registros administrado por Route 53.
  - **Ejemplo:** la zona `example.com` agrupa registros de `www`, `api` y correo.
- **TTL — Time To Live (tiempo de vida):** segundos durante los que un resolver puede conservar una respuesta en caché.
  - **Ejemplo:** con TTL `300`, el resolver puede reutilizar el valor durante cinco minutos.
- **A:** registro que dirige un nombre hacia una dirección IPv4.
  - **Ejemplo:** `www.example.com → 192.0.2.10`.
- **AAAA:** registro que dirige un nombre hacia una dirección IPv6.
  - **Ejemplo:** `www.example.com → 2001:db8::10`.
- **CNAME — Canonical Name:** alias que dirige un nombre hacia otro nombre DNS.
  - **Ejemplo:** `shop.example.com → stores.example.net`.
- **NS — Name Server:** identifica los servidores autoritativos de una zona.
  - **Ejemplo:** el dominio delega respuestas de `example.com` a los NS asignados a su zona.
- **CAA — Certification Authority Authorization:** indica qué autoridades certificadoras pueden emitir certificados para el dominio.
  - **Ejemplo:** limita la emisión a una CA autorizada por el propietario.
- **DS — Delegation Signer:** publica información usada para establecer una cadena de confianza de DNSSEC con una zona hija.
  - **Ejemplo:** el dominio padre contiene el DS que corresponde a la clave de la zona firmada.
- **MX — Mail Exchange:** indica servidores que reciben correo del dominio.
  - **Ejemplo:** `example.com` dirige su correo a `mail.example.com`.
- **NAPTR — Name Authority Pointer:** aplica reglas de transformación utilizadas por sistemas especializados.
  - **Ejemplo:** una aplicación de telefonía puede transformar un número en una dirección de servicio.
- **PTR — Pointer:** realiza resolución inversa desde una dirección IP hacia un nombre.
  - **Ejemplo:** una consulta inversa de una IP devuelve `host.example.com`.
- **SOA — Start of Authority:** contiene información administrativa y de control de la zona.
  - **Ejemplo:** incluye el servidor principal y parámetros utilizados por DNS.
- **TXT — Text:** almacena texto asociado al nombre.
  - **Ejemplo:** puede publicar una prueba de propiedad del dominio.
- **SPF — Sender Policy Framework:** formato histórico de registro para políticas de remitentes; actualmente estas políticas se publican normalmente dentro de registros TXT.
  - **Ejemplo:** una política indica qué servidores pueden enviar correo para el dominio.
- **SRV — Service:** publica el host y puerto de un servicio.
  - **Ejemplo:** un cliente descubre dónde se encuentra un servicio de comunicaciones.
- **VPC — Virtual Private Cloud:** red virtual aislada controlada por el cliente en AWS.
  - **Ejemplo:** una zona privada responde únicamente dentro de las VPC asociadas.

- **IP — Internet Protocol:** sistema de direccionamiento usado para localizar interfaces en una red.
  - **Ejemplo:** un registro A devuelve una dirección IPv4.
- **CA — Certificate Authority (autoridad certificadora):** entidad que emite y firma certificados digitales.
  - **Ejemplo:** un registro CAA limita qué CA puede emitir para el dominio.
- **DNSSEC — Domain Name System Security Extensions:** extensiones que añaden firmas criptográficas a DNS para validar la autenticidad de las respuestas.
  - **Ejemplo:** un registro DS ayuda a encadenar la confianza desde la zona padre hacia una zona firmada.

## Idea central

Route 53 responde consultas según los registros y políticas de una zona; no reemplaza al servidor web ni al recurso de destino.

**Ejemplo integrador:** el usuario consulta `www.example.com`. Route 53 responde con el valor configurado y su TTL; el resolver guarda esa respuesta y el navegador se conecta después al recurso indicado.

## Qué es Amazon Route 53

- Servicio DNS altamente disponible, escalable, totalmente administrado y autoritativo.
- También funciona como registrador de dominios.
- Permite comprobar la salud de los recursos.
- La fuente explica el nombre por el puerto DNS tradicional: `53`.

## Registros

Cada registro incluye:

- nombre de dominio o subdominio;
- tipo de registro;
- valor;
- política de enrutamiento;
- TTL, que controla cuánto tiempo guardan el registro los resolvers DNS.

## Tipos principales

| Tipo | Función |
| --- | --- |
| A | Nombre de host hacia IPv4. |
| AAAA | Nombre de host hacia IPv6. |
| CNAME | Nombre de host hacia otro nombre de host. No se usa en el apex de la zona. |
| NS | Servidores de nombres de la zona alojada. |

- La fuente también enumera CAA, DS, MX, NAPTR, PTR, SOA, TXT, SPF y SRV.

## Zonas alojadas

- **Pública:** registros que enrutan tráfico en Internet.
- **Privada:** registros que enrutan tráfico dentro de una o más VPC.
- Una zona es el contenedor de los registros de un dominio y sus subdominios.

## Claves de repaso

- Route 53 puede registrar el dominio, alojar sus registros y aplicar controles de salud.
- Un registro define cómo responder una consulta; una zona agrupa registros.
- Autoritativo significa que Route 53 contiene la respuesta oficial para la zona administrada.
